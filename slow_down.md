В функции slowDown LERP'а нет. Здесь используется совершенно другой физический принцип — линейное (постоянное) трение.
Давай разберем, как устроена эта функция и чем она отличается от LERP.

Как работает slowDown?

1. Math.sign(velocity) определяет, в какую сторону движется персонаж (1 если вправо/вниз, -1 если влево/вверх).
2. velocity - Math.sign(velocity) * FRICTION каждый кадр вычитает фиксированную величину FRICTION (трение) из скорости, направляя её к нулю. То есть скорость падает равномерно — например, ровно на 2 единицы за кадр.
3. if (Math.abs(velocity) <= FRICTION) return 0; — это «отсечка». Без неё скорость проскочила бы ноль и персонаж начал бы бесконечно дергаться туда-сюда вокруг нулевой отметки. Как только скорость становится меньше силы трения, игра жестко приравнивает её к 0.

Разница между LERP и Трение (FRICTION)

Чтобы разница была очевидной, давай сравним их поведение в таблице:

Критерий	Разгон через LERP (if)	Торможение через FRICTION (else)
Характер изменения	Нелинейный (экспоненциальный). В самом начале скорость меняется огромными скачками, а по мере приближения к цели — еле-еле.	Линейный (равномерный). Скорость уменьшается с одинаковой «силой» в каждом кадре.
Математика	Изменение зависит от расстояния до цели: чем дальше цель, тем сильнее рывок.	Изменение зависит от времени: каждый кадр отнимается строго фиксированное число.
Остановка/Достижение цели	Теоретически LERP никогда не достигает идеальной цели, он просто бесконечно приближается к ней (поэтому в играх его округляют).	Скорость гарантированно и ровно доходит до 0 благодаря проверке if (Math.abs(velocity) <= FRICTION).


Как выглядело бы торможение через LERP?

Если бы разработчик захотел сделать торможение тоже через LERP, функция slowDown не нуждалась бы во фрикции и знаках. Она бы плавно тянула скорость к 0 (целевая скорость при остановке):
javascript
// Пример торможения через LERP (в твоем коде этого нет, это для сравнения)
function slowDownLerp(velocity) {
  const STOP_SMOOTHING = 0.1; // 10% торможения за кадр
  return velocity + (0 - velocity) * STOP_SMOOTHING; 
  // или просто: return velocity * 0.9;
}
Используйте код с осторожностью.
При LERP-торможении персонаж сначала резко сбрасывал бы скорость, а потом очень долго и плавно «докатывался» до полной остановки. Но в твоем текущем коде персонаж останавливается равномерно и четко, как физическое тело, скользящее по поверхности.
